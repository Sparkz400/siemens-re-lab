# 2026-11-14 Non-Optimized S7-1500

## Hypothesis

If an S7-1500 block uses the **Standard** (non-optimized) memory layout, TIA
might store it as classic `LoadableCodeBlockData.BinaryData` instead of
`LoadablePlusCodeBlockData`. If true, the existing `AwlRegenerator` path would
decode S7-1500 code without plus decryption.

## Method

1. Copy `PlantB2` to `PlantB2-nonopt`.
2. Open it through Openness.
3. Set `FC_And.MemoryLayout = MemoryLayout.Standard`.
4. Compile the PLC.
5. Save, close, and export to objectframe XML.
6. Inspect the `FC_And` loadable class and attributes.

## Result

```text
block=FC_And layout before=Optimized
layout after=Standard
compile state=Success errors=0 warnings=0
```

Exported `FC_And`:

```text
loadable=Siemens.Simatic.Lang.Model.Blocks.LoadablePlusCodeBlockData
LoadType=PLUSBLOCK
OpenImmediateData=1500030030490000000802D5
UnencryptedCodeBinaryLength=23
OwnSignatureData=48 bytes
```

The block is still plus. The memory layout changes data access, not the code
format.

## Conclusion

Non-optimized S7-1500 blocks do **not** fall back to classic MC7. S7-1500
uses plus code regardless of memory layout. This route is closed.
